# digital-metrics agent instructions

Object detection evaluation library. Computes per-class precision, recall, F1, mAP50/75/50-95,
Cohen's kappa and Wilson confidence intervals from pandas DataFrames of ground truth and
predictions. Outputs `Metrics` objects, a confusion matrix, Excel dashboards and CI plots.
This repository is a GitHub fork (`BuckanovNikita/digital-metrics`) of an upstream project.
Read [DOCS.md](DOCS.md) for architecture, metric internals, the public API contract and operations.

## Layout

- `src/digital_metrics/` — the package. Flat public API in `__init__.py`; subpackages `engines/`,
  `matching/`, `scoring/`, `preprocess/`, `reporting/`, `backends/`, `inference/`, `tracking/`.
  Module map: DOCS.md § Module map.
- `tests/` — pytest suite; data fixtures in `tests/fixtures/`, shared fixtures in `tests/conftest.py`.
- `scripts/` — evaluation, backend comparison/profiling scripts and `local_release.py`.
- `fixtures/` — small synthetic GT/prediction CSVs plus outputs generated by `scripts/eval.py`.
- `docs/` — upstream user documentation (English and `.ru.md`), kept as is.
- `templates/CHANGELOG.md.j2`, `docs/changelog-history.md` — read by the release helper.

## Environment

- Python >= 3.11 (`requires-python`); `uv` with the committed `uv.lock`. Never use `pip` directly;
  `pip install digital-metrics[...]` appears only in user-facing install hints.
- Fresh worktree: `uv sync --locked --dev`.
- Optional extras: `uv sync --extra ultralytics` / `--extra torchmetrics` (both pull in torch),
  `uv sync --extra clearml` (torch-free). Add dependencies with `uv add`, never by hand-editing the lock.

## Checks

Run these directly before marking a PR ready:

```bash
uv run --locked --no-sync ruff check .                          # lint (config in pyproject.toml)
uv run --locked --no-sync mypy src/ scripts/local_release.py    # strict type check
uv run --locked --no-sync pytest                                # unit tests (serial)
uv run --locked --no-sync ruff format --check .                 # formatting (recommended, not gated)
uv build                                                        # wheel/sdist (readme = README.md)
```

- Coverage: `uv run --locked --no-sync pytest --cov=src/digital_metrics tests/`.
- `tests/test_local_release.py` builds real throwaway Git repositories and runs `uv lock --offline`,
  Python Semantic Release and `prek` against a fixture hook config; it is slower than the rest of the suite.
- Backend tests (`test_ultralytics_metrics.py`, `test_torchmetrics_metrics.py`) skip unless the
  extra is installed. Run them after `uv sync --extra <name>` when touching `backends/`.
- There is no CI. The checks above are the gate before a PR is marked ready.

## Architecture boundaries and hard constraints

- Core install stays torch-free and ClearML-free. `backends/`, `inference/` and `tracking/` import
  their extras lazily and raise `ImportError` with an install hint when absent.
- Each subpackage `__init__.py` re-exports its public names; internal code imports from the
  subpackage (`from .scoring import compute_map`); top-level `digital_metrics` keeps the API flat.
- `types.py`, `ci.py`, `validation.py` are the shared foundation (`types` depends on `ci`).
  `evaluation.py` orchestrates IO and dispatch; `calibration.py` selects thresholds; `engines/`
  (`NativeEngine`, `BackendEngine`) score.
- Library boundary (enforced by `tests/test_shared_architecture.py` with
  `docs/plans/shared-extraction/architecture.json`): `__init__.py`, `fixed.py`, `comparison.py`,
  `scoring/ap.py`, `scoring/__init__.py`, `reporting/dashboard.py`, `reporting/__init__.py` must
  not import `clearml_yolo`, `hydra` or `clearml`.
- The ClearML tracking layer sits on top of a finished `Evaluation`; core evaluation code never
  imports or knows about ClearML.
- Every public name, signature, default, attribute and exception in DOCS.md § Public API contract
  must survive any refactor. Keyword-only markers (`*`) are part of the contract.

## Decisions that bind code changes

- mAP is computed independently of P/R/F1 matching. Confidence filter and NMS apply to `preds_df`
  (P/R/F1/CM); `compute_map` always receives `_raw_preds_df` (Ultralytics two-path design).
- Classes absent from the evaluated split get `float("nan")` for `ap50`, `ap75`, `ap50_95`, never
  `0.0`, so `nanmean` excludes them.
- Defaults: `Evaluation` uses `matching_strategy="iou_prior"`, `ap_method="interp"`; `match_boxes`
  and `compute_map` default to `"greedy"`, and `compute_map` to `"continuous"`. Do not unify them.
- Native P/R/F1 and CM come from one `match_boxes` pass at a single IoU threshold. They are
  intentionally custom: do not try to make them numerically match YOLO console output.
- AP is backend-specific; native assignment may differ from backends. Compare, never assume parity.
- Confidence thresholds are selected only at realizable operating points (tie-group boundaries), so
  the optimised F1 equals the F1 obtained by `slice_by_conf`.
- Explicit backend thresholds carry exact TP/FP/FN and Wilson intervals; unthresholded or
  reconstructed summaries have `counts_observed=False` and NaN intervals.
- Input validation runs before filtering, suppression and unknown-label dropping. Unknown prediction
  classes are warned about and dropped identically on native and backend paths.
- Synthetic fixtures replace the unavailable original datasets; do not assert that historical
  large-dataset outputs are reproduced.

## Code standards

- Keep syntax and annotations valid for Python 3.11; do not add `from __future__ import annotations`.
- Fully annotate public functions; mypy runs `strict`. Scope `ignore_missing_imports` overrides to
  the affected modules; prefer stubs (`pandas-stubs`) to `Any`.
- Library code under `src/` logs with `loguru`, never `print()`; scripts keep their printed summaries.
- Use Pydantic for validated models and pytest for tests. Catch specific exceptions at a boundary
  that handles them; preserve the cause when translating.
- Preserve public imports, CLI output and exit codes, config precedence and serialized formats.
- Ruff: line length 120, target py311, rules `E F I UP B FBT`; do not widen the rule set or reformat
  unrelated code. Import sorting is a lint fix, not a formatter job.
- Simple over clever; small focused functions; no dead code, commented-out blocks or TODO stubs;
  English in code, comments and logs. Optimise only where profiling shows a bottleneck.
- Check current documentation of third-party APIs (ultralytics, torchmetrics, clearml, pandas,
  pydantic) instead of relying on memory.

## Tests

- Cover hand-computed cases on the `tiny_dataset` fixture: IoU edge cases; greedy, iou_prior and
  hungarian TP/FP/FN (iou_prior lets a lower-confidence, higher-IoU prediction win; hungarian TP
  >= greedy TP); AP on trivial detectors (1.0 / 0.0) for both AP methods; `compute_map` strategy
  divergence (greedy AP=1.0, iou_prior AP=0.5); CI bounds within [0,1]; full `Evaluation`
  round-trip; NMS containment and cross-class suppression.
- Unit tests use fake ClearML tasks; they do not demonstrate live ClearML authentication.

## Release and delivery

- Work items live in Linear: team `SIP`, project `digital-metrics`. Cite issues as `SIP-NN` only in
  GitHub and committed files (the repo is public); never paste Linear URLs or issue text there.
- One task branch and one PR per cohesive change; name the issue in the branch and PR title. The PR
  title is a Conventional Commit subject, e.g. `feat(scope): add X (SIP-NN)`.
- Open PRs against this fork, never the upstream parent:
  `gh pr create --repo BuckanovNikita/digital-metrics --base main`.
- Agents push task branches and open PRs; humans merge. Never push `main` or merge into it locally.
- Move the Linear issue to In Progress when starting and In Review when the checks pass; record the
  checks actually run. Done only after the PR is merged and acceptance criteria hold.
- Labels (reuse the existing ones, never create lowercase duplicates): one readiness label
  (`needs-triage`, `needs-info`, `ready-for-agent`, `ready-for-human`, `wontfix` = state Canceled)
  and one category label (`Bug`, `Feature`, `Improvement`) per issue.
- Put the PR link in the Linear issue; list every included `SIP-NN` in the PR description.
- Start dependent work only when its prerequisite is verified on its base branch. An In Review issue
  whose PR is merged moves to Done after its acceptance criteria are checked.
- Local releases are explicit: `uv run --locked --no-sync python scripts/local_release.py` on `main`
  (Python Semantic Release; `fix:`/`perf:` patch, `feat:` minor, breaking changes minor below 1.0).
  It edits only `pyproject.toml`, the root version in `uv.lock` and `CHANGELOG.md`, commits
  `chore(release): X.Y.Z`, tags `vX.Y.Z`, and never pushes or builds. Recovery:
  [docs/local-release.md](docs/local-release.md). Run it only when the owner explicitly asks; its
  commit and tag on `main` are the only allowed local commits on `main`. Agents never push them.
- `CHANGELOG.md` is generated (`local_release.py --changelog`); edit curated history through 0.5.3 in
  `docs/changelog-history.md`, never the generated entries.

## Known pitfalls

- `.pre-commit-config.yaml` and `local_release.py --install-hooks` are upstream files; the `prek` dev
  pin and the prek calls in `local_release.py` are fork changes. They stay because the upstream-owned
  `tests/test_local_release.py` needs a hook runner. Agents do not install hooks, so a release
  commit is ungated: run the Checks above on `main` before invoking a release.
- `scripts/eval.py` overwrites `fixtures/eval_*.csv/json`; it pins `greedy`/`continuous`, unlike the
  `Evaluation` defaults.
- `ruff` excludes `.agents`, `agent`, `.claude`; pass `--force-exclude` when giving explicit paths.
- Live ClearML checks must run against a ClearML deployment owned by this project in its own
  Kubernetes namespace with a `ResourceQuota` and teardown. The shared local Kubernetes test
  infrastructure is operated per the AGENTS.md and DOCS.md of the k8s-infra repository.

## Working agreement
- At the start of work, state the worktree path, the current branch and its relation to the default branch; say when remote refs were not fetched.
- Inspect existing and staged changes before editing. Preserve unrelated work and local overrides; stage only task-owned paths and inspect the staged diff.
- Report what each executed check establishes and what remains unverified; distinguish mocked checks, live outcomes and historical evidence. Clean up task-owned processes and temporary resources.
- Tests must exercise product code, never project tooling.
- Changes to behavior, interfaces, dependencies, security or operational policy need a fresh independent review after integration and verification. Small wording edits may be self-reviewed.
- Split large work into independent delegated tasks with explicit write ownership and acceptance evidence; delegated agents do not delegate further.
- Use Conventional Commits. Commit automatic formatting separately from logic. Local commits within the task scope need no approval.
- README.md is Russian; AGENTS.md and DOCS.md are English. Keep observed counts, timings and deployment status out of both files.
- Keep machine-specific paths, endpoints and settings in local configuration, not in these files.
